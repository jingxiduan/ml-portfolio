## 1. Overview

It takes **DiffusionOPSD**, an on-policy self-distillation method originally built for pixel
diffusion, and **migrates it to digital-human motion**. The Motion DiT of JoyVASA is frozen and
fine-tuned with LoRA, then post-trained with a **differentiable liveliness reward** so the
generated human blinks, nods and shifts gaze instead of holding a frozen mask. Rendering is
LivePortrait, which is never trained.

- Method source: https://github.com/worldbench/DiffusionOPSD · only the **method** is ported, not its backbone
- Backbone: JoyVASA `motion_generator_hubert_chinese`, frozen
- Renderer: LivePortrait, warp plus stitching plus pasteback
- Three target industries: **finance / real-estate / short-video**. Every industry target is
  **measured from real public human footage**, it is not hand-tuned.

**Honest boundary**: this is a method project, not a production talking-head video pipeline.
So far **only one 600 step smoke run** has finished.

**Two concepts that must not be confused**, they were mixed up once and caused a wrong call:

- `base` = the frozen pretrained model run on audio, **inference**
- `real` = real human motion coefficients copied over to drive the face, **also inference**
- neither column is trained. The job of training is to move the `base` column toward the
  `real` column.

## 6. How to reproduce

```bash
cd 07-talking-head-motion-opsd
source .venv/bin/activate            # environment setup: scripts/h20_render_setup.sh

# 1) environment, downloads JoyVASA, LivePortrait, HuBERT-chinese, about 2.5 GB, third_party is not in git
bash scripts/h20_render_setup.sh

# 2) training data, audio_public is not in git and must be rebuilt
python scripts/build_audio_segments.py --n-train 2000 --n-eval 100

# 3) measure the three industry real human bands
python scripts/calibrate_industry_bands.py      # -> outputs/industry_bands.json

# 4) train, this round's smoke: lr 1e-4 with 200 step warmup
CUDA_VISIBLE_DEVICES=0 python src/opsd_train_motion_v5.py \
  --out outputs/opsd_v5_finance_smoke --data-dir data/audio_public/train \
  --rounds 600 --lr 1e-4 --warmup 200 \
  --amp-target-deg 1.384 --amp-tol-deg 1.0 --jitter-cap-deg 0.188 --blink-target-mean 0.12

# 5) real-driven demo, the top block
python scripts/render_real_driven.py --video <clip> --portrait auto
python scripts/postprocess_video.py <in>.mp4 <out>_hq.mp4 --sr none
python scripts/build_demo_sbs.py --tag f3 --industry finance \
  --base ..._base_hq.mp4 --real ..._real_hq.mp4

# 6) two person grid demo, the middle block
python scripts/check_persona_clips.py && python scripts/add_gaze_checks.py
python scripts/build_persona_grid.py
```

**Why some weights are chunked**: GitHub has a hard **100 MB per file limit** and nothing goes
up without LFS, while the free LFS quota is only 1 GB and will not fit. So the 9 large weights,
the biggest at 1,084 MB, were split into 90 MB chunks.

To restore:

```bash
bash scripts/restore_chunks.sh     # reassembles into third_party/JoyVASA/pretrained_weights/...
```

environment, not material, and `scripts/h20_render_setup.sh` plus requirements rebuild it.

## 8. Known issues and next steps

1. **The trained model has no visualisation yet**: `scripts/render_industry_demo.py` points its
   manifest at `data/audio_ind/finance/*.wav`, but the audio actually lives in
   `data/audio_picked/` under different names. Fix the mapping and re-render. **First priority.**
2. **Only 600 steps of smoke ran**: the full 3000 step run and the real-estate and short-video
   industries are untouched.
3. **The real-driven column is still a target, not a result**: it copies real coefficients, the
   model has not learned it.
4. The short-video clip, s3, is bright at source, 140, and stays around 118 after grading, with
   0.9 percent of highlights clipped.
5. GitHub proxies and caches README images: **renaming the file, v8,** is the only reliable way
   to make the new version show up.
6. Early v2 and v3 overshot real human amplitude by 2.4 to 2.7x, which is where the uncanny
   valley came from. From v4 on, a **peaked reward centred on the measured band** holds it down,
   0.84 to 0.90x of target with no overshoot.
